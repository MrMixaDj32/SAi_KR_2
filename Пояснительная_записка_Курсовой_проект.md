# ВВЕДЕНИЕ

**Актуальность темы.** Рост уровня автомобилизации современных городов приводит к резкому увеличению нагрузки на улично-дорожную сеть (УДС). Традиционные жесткопрограммные системы светофорного регулирования, функционирующие по заранее рассчитанным статическим суточным планам (согласно ГОСТ Р 52289), не обладают достаточной гибкостью и не способны эффективно реагировать на стохастические колебания интенсивности транспортных потоков, локальные заторы и неравномерность распределения очередей. Следствием этого являются многокилометровые заторы, увеличение времени задержки транспорта, перерасход топлива и ухудшение экологической обстановки в городских агломерациях.

Особую сложность представляют магистральные транспортные коридоры со сложной планировочной структурой. Ярким примером является ул. Северная в г. Краснодаре на участке от ул. Октябрьской до ул. Красной. Данный коридор характеризуется разнородностью примыкающих направлений (односторонняя ул. Рашпилевская, магистральная ул. Красная с широким пешеходным бульваром и сложной схемой левых и правых поворотов), а также взаимным влиянием очередей близкорасположенных перекрестков. Возникновение затора на одном узле мгновенно блокирует смежные перекрестки (эффект «домино» или gridlock).

Внедрение мультиагентных систем адаптивного управления (Multi-Agent Traffic Control Systems, MATCS) на базе искусственных нейронных сетей и продукционных баз правил позволяет локальным контроллерам динамически продлевать или сокращать фазы сигналов, координировать пропуск пачек автомобилей («зеленая волна») и предотвращать блокировку перекрестков в режиме реального времени.

**Цель работы** — проектирование, алгоритмическая разработка и программная реализация интерактивного моделирующего комплекса мультиагентного адаптивного управления светофорным регулированием транспортного коридора ул. Северной, обеспечивающего сокращение времени задержки автомобилей и предотвращение заторов по сравнению с классическим регулированием по ГОСТ.

**Задачи исследования:**
1. Выполнить системный анализ транспортного коридора ул. Северной (перекрестки Октябрьская, Рашпилевская, Красная), включая геометрию 53 полос движения, конфликтные точки и циклограммы светофоров.
2. Разработать микроскопическую модель движения транспортных средств на базе модифицированной модели IDM (Intelligent Driver Model) с поддержкой кинематики поворотов и предотвращения коллизий.
3. Спроектировать гибридную архитектуру агента управления: искусственную нейронную сеть прямого распространения (MLP) для анализа многомерного вектора очередей и продукционную экспертную базу правил безопасности (`SafetyRuleEngine`).
4. Разработать алгоритм межагентной координации для формирования сквозной динамической «зеленой волны» вдоль магистрали.
5. Реализовать генетический алгоритм (ГА) для автоматизированного обучения синаптических весов агентов в условиях стохастического притока машин.
6. Разработать программный комплекс на C# (.NET 8, Windows Forms, GDI+) с визуализацией микротрафика, приборными панелями узлов (HUD) и модулем сравнительного лабораторного A/B тестирования.
7. Провести серию экспериментов на различных сценариях нагрузки и выполнить сравнительную оценку эффективности адаптивного ИИ и фиксированного цикла ГОСТ.

**Объект исследования** — процессы движения транспортных потоков в регулируемом магистральном коридоре улично-дорожной сети.

**Предмет исследования** — методы, алгоритмы и программные средства мультиагентного нейросетевого и продукционного адаптивного управления светофорными объектами.

**Практическая значимость** — разработанное программное обеспечение представляет собой законченный моделирующий комплекс, который может быть использован для предпроектного анализа схем организации дорожного движения (ОДД), обоснования внедрения адаптивных контроллеров в органах управления городским транспортом, а также в учебном процессе вузов по дисциплинам «Проектирование информационных систем», «Системный анализ и принятие решений» и «Интеллектуальные транспортные системы».

# 1 ПРЕДПРОЕКТНОЕ ИССЛЕДОВАНИЕ И СИСТЕМНЫЙ АНАЛИЗ ТРАНСПОРТНОГО КОРИДОРА

## 1.1 Общее описание предметной области и транспортного узла

Предметной областью исследования является процесс организации дорожного движения на регулируемых перекрестках магистральной улично-дорожной сети крупного города. В качестве расчетно-модельного полигона выбран фрагмент центрального транспортного коридора г. Краснодара — ул. Северная на участке от ул. Октябрьской до ул. Красной.

Данный участок представляет собой один из наиболее загруженных транспортных узлов города со следующими планировочными особенностями:
1. **Магистраль ул. Северной:** многополосная артерия с непрерывным двухсторонним движением (по 2–3 полосы в каждом направлении: восточном и западном). Она принимает интенсивные транзитные потоки между западными и восточными округами города.
2. **Перекресток 1 (ул. Северная / ул. Октябрьская):** классический регулируемый перекресток с 6 входящими полосами движения.
3. **Перекресток 2 (ул. Северная / ул. Рашпилевская):** перекресток с примыканием улицы с односторонним движением (ул. Рашпилевская к югу от Северной является строго односторонней, движение направлено сверху вниз по двум полосам). На перекрестке реализованы выделенные правые повороты на Рашпилевскую в северном и южном направлениях.
4. **Перекресток 3 (ул. Северная / ул. Красная):** наиболее сложный узел (10 входящих направлений). Ул. Красная разделена широким пешеходным бульваром на два обособленных рукава:
   - Западный рукав: одностороннее движение сверху вниз (с севера на юг);
   - Восточный рукав: движение снизу вверх (с юга на север);
   - Поворот налево с ул. Красной на ул. Северную осуществляется через промежуточный накопительный карман между бульварами со специальным промежуточным светофором;
   - С крайней левой полосы южного рукава Красной разрешено движение как налево на Северную, так и прямо в северном направлении;
   - Организованы выделенные бесконфликтные полосы правого поворота с Северной на Красную с параллельными траекториями движения.

## 1.2 Назначение системы и ее роль в интеллектуальных транспортных системах (ИТС)

Разрабатываемая система относится к классу специализированного программного обеспечения имитационного микромоделирования и адаптивного управления дорожным движением.

**Основное назначение системы:**
- Моделирование движения индивидуальных транспортных средств с физически правдоподобными кинематическими характеристиками;
- Сравнение классического жесткого пофазного управления по ГОСТ Р 52289 и мультиагентного адаптивного управления на едином потоке трафика;
- Координация смежных светофорных объектов для реализации адаптивной «зеленой волны» вдоль ул. Северной;
- Предотвращение блокировки перекрестков стоящими автомобилями в соответствии с п. 13.2 ПДД РФ (Anti-Gridlock).

Система позволяет анализировать влияние параметров светофорных циклов на среднюю задержку транспорта, максимальную длину очередей и пропускную способность узла.

## 1.3 Входная информация: геометрия полос, интенсивности потоков и матрица фаз

### Геометрические параметры сети
Входной информацией для моделирования является топологическая структура сети полос (Lane):
- Всего в коридоре смоделировано **53 полосы движения**, заданных сплайнами координат точек перегиба (Waypoints);
- Масштаб пространственного отображения: $1 \text{ метр} = 3.5 \text{ пикселей}$;
- Габариты легковых автомобилей: длина $4.5$ м, ширина $1.8$ м; грузовых: длина $7.0$ м, ширина $2.2$ м.

### Параметры транспортного притока (Inflows)
Интенсивности притока задаются в автомобилях в час (авт/ч) и динамически регулируются пользователем:
- Входной поток по ул. Северной с запада ($Q_{\text{sev\_w}}$): от 800 до 2200 авт/ч;
- Входной поток по ул. Северной с востока ($Q_{\text{sev\_e}}$): $0.9 \cdot Q_{\text{sev\_w}}$;
- Поток по ул. Красной прямо ($Q_{\text{kras\_str}}$): 300–800 авт/ч;
- Поток по ул. Красной налево ($Q_{\text{kras\_left}}$): 150–500 авт/ч;
- Боковые притоки с ул. Октябрьской и Рашпилевской: 250–500 авт/ч.

### Матрица фаз светофорных циклов (по ГОСТ Р 52289)
Для каждого перекрестка определен набор фаз разъезда с фиксированными базовыми длительностями:
- Фаза 1 (Магистральная): зеленый сигнал для ул. Северной (длительность 40–45 с);
- Фаза 2 (Второстепенная): зеленый сигнал для поперечных улиц (длительность 20–32 с);
- Переходные интервалы: желтый сигнал $t_{\text{yellow}} = 3.0$ с, кругом красный сигнал (промежуточный такт безопасности) $t_{\text{all\_red}} = 2.0$ с.

## 1.4 Выходные показатели эффективности регулирования

Система непрерывно регистрирует и агрегирует следующие выходные метрики:
1. **Среднее время задержки транспортного средства ($\bar{d}$, с):**
   $$\bar{d} = \frac{1}{N} \sum_{i=1}^{N} t_{\text{wait}, i}$$
   где $t_{\text{wait}, i}$ — суммарное время, в течение которого скорость $i$-го автомобиля была менее $0.5$ м/с.
2. **Суммарная длина очередей ($Q_{\text{total}}$, авт.):** количество стоящих автомобилей перед всеми стоп-линиями.
3. **Обслуженное количество транспортных средств ($N_{\text{passed}}$, авт.):** автомобили, полностью завершившие проезд через моделируемый коридор.
4. **Доля безостановочного проезда («Зеленая волна», %):**
   $$P_{\text{wave}} = \frac{N_{\text{stops}=0}}{N} \cdot 100\%$$
5. **Поузловая задержка ($d_{\text{Okt}}, d_{\text{Rash}}, d_{\text{Kras}}$, с):** среднее время ожидания на конкретных перекрестках.

## 1.5 Концептуальная модель функционирования распределенной системы

Функционирование системы основано на парадигме распределенного мультиагентного управления (Multi-Agent System). Каждый перекресток снабжен автономным агентом (`TrafficAgent`), который:
1. Опрашивает виртуальные детекторы входящих и выходящих полос своего узла;
2. Обменивается сообщениями о приближении транспортных взводов с соседними агентами коридора (West-East координация);
3. Формирует вектор локального состояния $S \in \mathbb{R}^8$;
4. Пропускает вектор через нейросетевой блок принятия решений;
5. Передает выходное действие в продукционную базу правил безопасности (`SafetyRuleEngine`), которая санкционирует или блокирует переключение сигналов;
6. Управляет исполнительным механизмом светофорного контроллера.

## 1.6 Аналитический обзор существующих программных решений

На практике и в исследовательской деятельности применяются следующие программные системы:
- **PTV Vissim:** мировой эталон микромоделирования. Обладает высочайшей детализацией, однако является закрытым коммерческим продуктом высокой стоимости, не предоставляющим простого встроенного инструментария обучения легковесных нейросетевых агентов на C#.
- **SUMO (Simulation of Urban MObility):** открытый инструмент моделирования дорожного движения. Поддерживает интерфейс TraCI для подключения внешних Python-скриптов, однако требует сложной конфигурации и обладает высоким порогом вхождения для демонстрации на настольных ПК.
- **Aimsun:** мощная среда макро- и микромоделирования, ориентированная преимущественно на транспортное проектирование институтов генеральных планов.

Разрабатываемая в рамках курсового проекта система отличается автономностью (single-executable Windows Forms приложение на .NET 8), отсутствием внешних тяжелых зависимостей, встроенным микрофизическим движком с высокоскоростной отрисовкой через GDI+, интегрированным генетическим алгоритмом обучения и прямым интерактивным модулем A/B сравнительного анализа.

## 2.2 Математическое и алгоритмическое моделирование

### 2.2.1 Модель следования за лидером (IDM) и динамика транспортных средств

Движение каждого автомобиля вдоль центральной линии полосы описывается модифицированной моделью Intelligent Driver Model (IDM). Ускорение автомобиля $\dot{v}$ рассчитывается по дифференциальному уравнению:

$$\dot{v} = a \left[ 1 - \left( \frac{v}{v_0} \right)^\delta - \left( \frac{s^*(v, \Delta v)}{s} \right)^2 \right]$$

где:
- $v$ — текущая скорость ТС;
- $v_0$ — желаемая скорость на свободной дороге ($16.6$ м/с, что соответствует 60 км/ч);
- $\delta$ — показатель степени ускорения (принято $\delta = 4$);
- $s$ — фактическая дистанция до бампера впереди идущего автомобиля (или стоп-линии);
- $a$ — максимальное комфортное ускорение ($2.5$ м/с$^2$);
- $b$ — комфортное торможение ($3.5$ м/с$^2$).

Желаемая динамическая дистанция $s^*(v, \Delta v)$ определяется формулой:

$$s^*(v, \Delta v) = s_0 + \max\left(0,\, v T + \frac{v \cdot \Delta v}{2 \sqrt{a \cdot b}}\right)$$

где:
- $s_0$ — минимальная дистанция в заторе ($2.0$ м);
- $T$ — безопасный временной интервал следования ($1.2$ с);
- $\Delta v = v - v_{\text{lead}}$ — разность скоростей текущего автомобиля и лидера.

При приближении к запрещающему сигналу светофора стоп-линия интерпретируется моделью как неподвижное виртуальное препятствие ($v_{\text{lead}} = 0$).

### 2.2.2 Архитектура локального агента управления перекрестком

Каждый агент $i \in \{1, 2, 3\}$ функционирует в дискретном цикле с периодом опроса $\tau = 1.0$ с. Структура агента объединяет:
1. **Перцептивный блок:** сбор метрик с полос перекрестка и получение телеметрии от соседей;
2. **Нейросетевой блок:** прямое распространение сигнала через обученный персептрон;
3. **Экспертный блок:** проверка решения на соответствие правилам безопасности и ПДД;
4. **Исполнительный блок:** отправка команды на удержание текущей фазы (`ExtendedGreenLimit`) или инициирование фазового перехода.

### 2.2.3 Структура и векторизация входных признаков нейросети (MLP 8-8-1)

Входной вектор состояния агента $S = (s_1, s_2, \dots, s_8)^T \in [0, 1]^8$ формируется по следующим правилам:
1. $s_1 = \min(1.0, Q_{\text{green}} / 30.0)$ — нормализованная длина очереди на разрешенном направлении;
2. $s_2 = \min(1.0, Q_{\text{red}} / 30.0)$ — нормализованная длина очереди на запрещенном направлении;
3. $s_3 = \bar{v}_{\text{green}} / 16.6$ — относительная средняя скорость потока на зеленых полосах;
4. $s_4 = \bar{v}_{\text{red}} / 16.6$ — относительная средняя скорость потока на красных полосах;
5. $s_5 \in \{0.0, 1.0\}$ — индикатор типа фазы (1.0 — магистраль Северной, 0.0 — боковая улица);
6. $s_6 = \min(1.0, t_{\text{phase}} / 60.0)$ — относительное время нахождения в текущей фазе;
7. $s_7 = \min(1.0, Q_{\text{neighbors}} / 40.0)$ — очередь на подходах смежных перекрестков;
8. $s_8 = \frac{1}{2} \left( \frac{Q_{\text{red}} - Q_{\text{green}}}{30.0} + 1.0 \right)$ — градиент локального транспортного давления (Max-Pressure differential).

Нейронная сеть представляет собой многослойный персептрон (MLP) с одним скрытым слоем:
- Входной слой: 8 нейронов;
- Скрытый слой: 8 нейронов, функция активации $\tanh(x)$;
- Выходной слой: 1 нейрон, логистическая функция активации:
  $$\sigma(z) = \frac{1}{1 + e^{-z}}$$
- Значение выхода $y \in [0, 1]$ интерпретируется как запрос на смену фазы при $y \ge 0.5$.

### 2.2.4 Продукционная база правил безопасности и координации коридора

Решение нейронной сети передается в продукционную базу правил (`SafetyRuleEngine`). Правила организованы по приоритетной схеме:

- **Правило 1 (Ограничение минимальной длительности такта по ГОСТ Р 52289):**  
  ЕСЛИ $t_{\text{phase}} < t_{\text{min}}$ ТО запретить смену фазы.  
  ($t_{\text{min}} = 25$ с для Северной, $14$ с для боковых улиц).
- **Правило 2 (Принудительный сброс по предельному времени):**  
  ЕСЛИ $t_{\text{phase}} \ge t_{\text{max}}$ ТО разрешить немедленную смену фазы.  
  ($t_{\text{max}} = 1.5 \cdot t_{\text{base}}$).
- **Правило 3 (Запрет вмешательства в переходных тактах):**  
  ЕСЛИ активен желтый или All-Red сигнал ТО блокировать любые переключения.
- **Правило 5 (Координация «Зеленой волны»):**  
  ЕСЛИ активна фаза Северной И от соседнего узла приближается взвод автомобилей ($v > 1.5$ м/с) ТО продлить зеленый сигнал коридора.
- **Правило 7 (Ранний сброс пустой боковой улицы, Early Cut-off):**  
  ЕСЛИ активна боковая фаза И $t_{\text{phase}} \ge t_{\text{min}}$ И очередь на боковой улице равна 0 И на Северной накопилась очередь ТО досрочно вернуть зеленый на магистраль.
- **Правило 8 (Anti-Gridlock защита магистрали):**  
  ЕСЛИ очередь на Северной превысила 12 машин и в 1.5 раза больше боковой ТО форсировать переключение в пользу магистрали.
- **Правило 4c (Защита локального взвода):**  
  ЕСЛИ нейросеть запрашивает смену фазы ($y \ge 0.5$), но по полосе продолжается плотное безостановочное движение пачки машин ТО отложить переключение до проезда взвода.

### 2.2.5 Генетический алгоритм обучения агентов

Для подбора матрицы весовых коэффициентов $W$ нейронных сетей всех трех агентов используется генетический алгоритм:
- Геном особи представляет собой сплошной вещественный вектор размерности $L = 3 \times (8 \times 8 + 8 + 8 \times 1 + 1) = 243$ гена;
- Размер популяции: 20 особей;
- Количество поколений: 15;
- Целевая функция приспособленности (Fitness Function):
  $$F = \frac{10000}{\bar{d} \cdot 1.5 + Q_{\text{max}} \cdot 2.0 + \text{Stops} \cdot 0.5 + 1.0}$$
  где $\bar{d}$ — средняя задержка, $Q_{\text{max}}$ — пиковая очередь, $\text{Stops}$ — суммарное число остановок. Максимизация $F$ эквивалентна минимизации потерь времени и заторов.

## 2.3 Проектирование архитектуры приложения

### 2.3.1 Структурная схема программного обеспечения

Архитектура системы построена по модульному принципу и включает следующие основные подсистемы:

5. **Графический интерфейс пользователя (`Form1`, `ComparisonReportForm`):** отображение УДС на базе GDI+, панели телеметрии и дашборд метрик.

### 2.3.2 Функциональное моделирование процессов (IDEF0)

На контекстной диаграмме A-0 процесс верхнего уровня «Управление дорожным движением транспортного коридора» преобразует входные потоки транспортных средств в обслуженный трафик с минимальными задержками под воздействием правил ПДД РФ и нормативов ГОСТ Р 52289 при управлении контроллерами перекрестков.

Декомпозиция диаграммы A0 включает 4 функциональных блока:
- A1: Моделирование движения ТС и сбор пространственных данных;
- A2: Межагентный обмен и оценка локальных состояний перекрестков;
- A3: Формирование управляющего воздействия (Нейросеть + База правил);
- A4: Фиксация статистических показателей и формирование сравнительной аналитики.

### 2.3.3 UML-моделирование

В проекте построены следующие UML-диаграммы:
- **Диаграмма компонентов:** взаимосвязь модулей `Presentation Layer` (UI), `Domain Layer` (Traffic Simulation Engine, Agent Intelligence), `Optimization Layer` (Genetic Trainer) и `Reporting Layer` (A/B Comparison Engine).
- **Диаграмма последовательности:** цикл взаимодействия таймера симуляции `TmrSim`, ядра `SimulationEngine`, полос `Lane`, агентов `TrafficAgent` и правил `SafetyRuleEngine` на каждом шаге интегрирования $\Delta t$.
- **Диаграмма состояний перекрестка:** переходы `Green` $\to$ `Yellow` $\to$ `AllRed` $\to$ `Green (следующая фаза)` с динамическим удержанием по `ExtendedGreenLimit`.
- **Диаграмма прецедентов (Use Case):** сценарии пользователя-оператора (запуск/пауза, смена режимов, выбор сценариев, запуск генетического обучения, генерация сравнительного A/B отчета).

## 3.4 Реализация модуля сравнительного анализа (A/B эксперимент)

Для объективного научного доказательства преимуществ адаптивного регулирования разработан модуль `ComparisonRunner`. Эксперимент проводится по схеме *Ceteris Paribus* («при прочих равных условиях»):
1. Инициализируется симулятор с фиксированным циклом ГОСТ Р 52289 со случайным зерном трафика `seed = 42`. Выполняется моделирование на интервале 150–180 секунд.
2. Инициализируется второй симулятор с режимом Мультиагентного ИИ с идентичным генератором псевдослучайных чисел (`seed = 42`) и точно такими же параметрами входящих потоков. Обученные веса нейросетей переносятся из основной формы.
3. Собираются интегральные показатели: средняя задержка, длина очередей, пропускная способность, процент безостановочного проезда («зеленая волна») и поузловые задержки.
4. Результаты выводятся в отдельном модальном окне `ComparisonReportForm` с возможностью экспорта текстового заключения в буфер обмена.

### Листинг А.1 — Класс TrafficAgent.cs (Агент адаптивного управления перекрестком)
`csharp
using System;
using System.Linq;

namespace SAi_KR
{
    public class TrafficAgent
    {
        public Intersection Node { get; }
        public NeuralNetwork Brain { get; }
        public SafetyRuleEngine RuleEngine { get; }

        public TrafficAgent? NeighborWest { get; set; }
        public TrafficAgent? NeighborEast { get; set; }

        public string CurrentDecisionText { get; set; } = "Ожидание такта";
        public double CurrentBrainOutput { get; set; } = 0.0;
        public bool IsCoordinatingWave { get; set; } = false;
        public int LastOpposingQueue { get; set; } = 0;
        public int LastGreenQueue { get; set; } = 0;

        public TrafficAgent(Intersection node, Random rand)
        {
            Node = node;
            Brain = new NeuralNetwork(8, 8, 1, rand);
            RuleEngine = new SafetyRuleEngine();
        }

        public double[] CollectState()
        {
            double[] state = new double[8];
            int currentPhase = Node.CurrentPhaseIndex;

            // 1. Очередь на разрешенном (зеленом) направлении
            int greenQueue = 0;
            double greenSpeedSum = 0;
            int greenVehCount = 0;
            if (currentPhase < Node.Phases.Count)
            {
                foreach (int laneIdx in Node.Phases[currentPhase].GreenLaneIndices)
                {
                    if (laneIdx < Node.IncomingLanes.Count)
                    {
                        var l = Node.IncomingLanes[laneIdx];
                        greenQueue += l.GetQueueLength();
                        if (l.Vehicles.Count > 0)
                        {
                            greenSpeedSum += l.Vehicles.Sum(v => v.Speed);
                            greenVehCount += l.Vehicles.Count;
                        }
                    }
                }
            }
            state[0] = Math.Min(1.0, greenQueue / 30.0);

            // 2. Очередь на запрещенном (красном) направлении
            int opposingQueue = 0;
            double redSpeedSum = 0;
            int redVehCount = 0;
            for (int i = 0; i < Node.IncomingLanes.Count; i++)
            {
                if (currentPhase < Node.Phases.Count && !Node.Phases[currentPhase].GreenLaneIndices.Contains(i))
                {
                    var l = Node.IncomingLanes[i];
                    opposingQueue += l.GetQueueLength();
                    if (l.Vehicles.Count > 0)
                    {
                        redSpeedSum += l.Vehicles.Sum(v => v.Speed);
                        redVehCount += l.Vehicles.Count;
                    }
                }
            }
            state[1] = Math.Min(1.0, opposingQueue / 30.0);

            // 3. Средняя скорость на разрешенных полосах
            state[2] = greenVehCount > 0 ? Math.Min(1.0, (greenSpeedSum / greenVehCount) / 16.6) : 1.0;

            // 4. Средняя скорость на запрещенных полосах
            state[3] = redVehCount > 0 ? Math.Min(1.0, (redSpeedSum / redVehCount) / 16.6) : 0.0;

            // 5. Тип активной фазы (1.0 = Северная магистраль, 0.0 = боковая улица)
            bool isMajor = currentPhase == 0;
            state[4] = isMajor ? 1.0 : 0.0;

            // 6. Относительное время фазы
            state[5] = Math.Min(1.0, Node.TimeInCurrentPhase / 60.0);

            // 7. Очередь на соседних узлах по коридору
            int neighborIncomingQueue = 0;
            if (NeighborEast != null && NeighborEast.Node.IncomingLanes.Count >= 4)
                neighborIncomingQueue += NeighborEast.Node.IncomingLanes.Skip(2).Take(2).Sum(l => l.GetQueueLength());
            if (NeighborWest != null && NeighborWest.Node.IncomingLanes.Count >= 2)
                neighborIncomingQueue += NeighborWest.Node.IncomingLanes.Take(2).Sum(l => l.GetQueueLength());
            state[6] = Math.Min(1.0, neighborIncomingQueue / 40.0);

            // 8. Разность давлений (Max-Pressure differential): (Q_opposing - Q_green)
            double deltaQ = (opposingQueue - greenQueue) / 30.0;
            state[7] = Math.Max(0.0, Math.Min(1.0, (deltaQ + 1.0) / 2.0));

            return state;
        }

        public (bool SwitchRequested, string Reason) Decide()
        {
            double[] inputs = CollectState();
            double[] output = Brain.Forward(inputs);

            int currentPhase = Node.CurrentPhaseIndex;
            bool isMajor = currentPhase == 0;

            int opposingQueue = 0;
            for (int i = 0; i < Node.IncomingLanes.Count; i++)
            {
                if (currentPhase < Node.Phases.Count && !Node.Phases[currentPhase].GreenLaneIndices.Contains(i))
                    opposingQueue += Node.IncomingLanes[i].GetQueueLength();
            }

            int greenQueue = 0;
            int approachingPlatoon = 0;
            double greenSpeedSum = 0;
            int greenVehiclesCount = 0;
            if (currentPhase < Node.Phases.Count)
            {
                foreach (int laneIdx in Node.Phases[currentPhase].GreenLaneIndices)
                {
                    if (laneIdx < Node.IncomingLanes.Count)
                    {
                        var l = Node.IncomingLanes[laneIdx];
                        greenQueue += l.GetQueueLength();
                        approachingPlatoon += l.Vehicles.Count(v => v.Speed > 1.5);
                        if (l.Vehicles.Count > 0)
                        {
                            greenSpeedSum += l.Vehicles.Sum(v => v.Speed);
                            greenVehiclesCount += l.Vehicles.Count;
                        }
                    }
                }
            }
            double averageGreenSpeed = greenVehiclesCount > 0 ? (greenSpeedSum / greenVehiclesCount) : 0;

            // Адаптивные границы фазы:
            // Для магистрали Северной: сохраняем высокую пропускную способность (минимум 25с, максимум 150%)

            double minGreen;
            double maxGreen;
            if (isMajor)
            {
                minGreen = Math.Max(25.0, baseDuration * 0.65);
                maxGreen = baseDuration * 1.5;
            }
            else
            {
                minGreen = Math.Max(14.0, baseDuration * 0.65);
                maxGreen = Math.Max(18.0, baseDuration * 1.35);
            }

            // Координация «зеленой волны»: определение реального приближения взвода от соседей
            // Проверяем не только фазу соседа, но и наличие движущихся машин на его зеленых полосах
            bool upstreamWaveApproaching = false;
            if (isMajor) // Координация волны только для магистральной фазы Северной
            {
                if (NeighborWest != null && NeighborWest.Node.CurrentPhaseIndex == 0 && NeighborWest.Node.TimeInCurrentPhase >= 4.0)
                {
                    // Проверяем, есть ли реально движущиеся машины на зеленых полосах соседа

        /// <summary>
        /// Механизм логического вывода (прямой вывод) для верификации решений нейросети
        /// </summary>
        public bool ValidatePhaseSwitch(TrafficFacts facts, out string ruleTriggered)
        {
            FiredRules.Clear();

            // Правило 1: Запрет переключения во время переходного такта (желтого сигнала / AllRed)
            FiredRules.Add("Оценка Правила 1 (Желтый сигнал)");
            if (facts.IsYellowActive)
            {
                ruleTriggered = "Правило 1: Активен такт желтого сигнала. Переключение заблокировано.";
                FiredRules.Add("-> " + ruleTriggered);
                return false;
            }

            // Правило 6: Приоритетный проезд экстренных служб.
            FiredRules.Add("Оценка Правила 6 (Экстренные службы)");
            if (facts.EmergencyVehicleDetected)
            {
                ruleTriggered = "Правило 6: Приоритетный проезд экстренных служб.";
                FiredRules.Add("-> " + ruleTriggered);
                return true;
            }

            // Правило 2: Запрет переключения до истечения минимальной длительности фазы
            FiredRules.Add("Оценка Правила 2 (Минимальная длительность)");
            if (facts.CurrentPhaseDuration < facts.MinPhaseDuration)
            {
                ruleTriggered = "Правило 2: Минимальный интервал зеленого сигнала не достигнут.";
                FiredRules.Add("-> " + ruleTriggered);
                return false;
            }

            // Правило 3: Принудительное переключение при превышении лимита времени удержания
            FiredRules.Add("Оценка Правила 3 (Максимальное удержание)");
            if (facts.CurrentPhaseDuration >= facts.MaxPhaseDuration && facts.OpposingQueueLength > 0)
            {
                ruleTriggered = "Правило 3: Превышен лимит удержания фазы при наличии очереди на поперечном направлении.";
                FiredRules.Add("-> " + ruleTriggered);
                return true;
            }

            // Правило 5: Динамическая разгрузка магистрального коридора Северной и координация «зеленой волны»
            FiredRules.Add("Оценка Правила 5 (Удержание коридора Северной)");
            if (facts.CurrentPhaseDuration < (facts.MinPhaseDuration + facts.MinGreenExtension) && facts.AverageGreenLaneSpeed > 5.0)
            {
                ruleTriggered = "Правило 5: Продление зеленого для группы движущихся ТС (скорость > 5 м/с).";
                FiredRules.Add("-> " + ruleTriggered);
                return false;
            }

            if (facts.IsMajorCorridorPhase && facts.CurrentPhaseDuration < facts.MaxPhaseDuration)
            {
                if (facts.IsUpstreamCorridorGreen)
                {
                    ruleTriggered = "Правило 5: Координация «зеленой волны» — прием пакета автомобилей по коридору.";
                    FiredRules.Add("-> " + ruleTriggered);
                    return false;
                }
            }

            // Фаза боковой улицы сбрасывается ТОЛЬКО если на ней действительно нет ни стоящих (GreenQueueLength == 0),
            // ни движущихся машин (ApproachingPlatoonCount == 0), и истек минимальный такт безопасности.
            FiredRules.Add("Оценка Правила 7 (Досрочный возврат на магистраль)");
            if (!facts.IsMajorCorridorPhase

                && facts.GreenQueueLength == 0 
                && facts.ApproachingPlatoonCount == 0

                FiredRules.Add("-> " + ruleTriggered);
                return true;
            }

            // Правило 8: Принудительный возврат к магистрали при критическом накоплении на Северной
            // Срабатывает только если на Северной образовалась большая очередь (>= 12),
            // которая значительно превышает очередь на боковой улице, и боковая улица уже получила гарантированный зеленый.
            FiredRules.Add("Оценка Правила 8 (Приоритет магистрали)");
            if (!facts.IsMajorCorridorPhase 
                && facts.CurrentPhaseDuration >= facts.MinPhaseDuration
                && facts.OpposingQueueLength >= 12 
                && facts.OpposingQueueLength > facts.GreenQueueLength * 1.5)
            {
                ruleTriggered = "Правило 8: Критическое накопление очереди на магистрали Северной. Возврат зеленого сигнала.";
                FiredRules.Add("-> " + ruleTriggered);
                return true;
            }

            // Правило 4: Санкционирование решения нейросети
            FiredRules.Add("Оценка Правила 4 (Решение нейросети)");
            if (facts.NetworkDecisionOutput >= 0.5)

                    FiredRules.Add("-> " + ruleTriggered);
                    return false;
                }

                // Удержание зеленого на боковой улице при наличии очереди
                if (!facts.IsMajorCorridorPhase && facts.GreenQueueLength > 0 && facts.GreenQueueLength >= facts.OpposingQueueLength)
                {
                    ruleTriggered = "Правило 4d: Решение ИНС отклонено — на боковой улице сохраняется очередь.";

                FiredRules.Add("-> " + ruleTriggered);
                return true;
            }

            ruleTriggered = "Правило по умолчанию: Продление текущей фазы.";
            FiredRules.Add("-> " + ruleTriggered);
            return false;
        }

            Name = name;

        public void AddOutgoingLane(Lane lane) => OutgoingLanes.Add(lane);
        public void AddPhase(TrafficPhase phase) => Phases.Add(phase);

        {
            int index = IncomingLanes.IndexOf(lane);
            if (index == -1) return false;

            // На желтый и полностью красный сигнал проезд запрещен всем направлениям
            if (CurrentState == LightState.Yellow || CurrentState == LightState.AllRed)
                return true;

            // На зеленый едут только полосы текущей активной фазы
            return !Phases[CurrentPhaseIndex].GreenLaneIndices.Contains(index);
        }

        /// Позволяет агенту ИИ динамически продлить текущую зелёную фазу.

                double effectiveDuration = ExtendedGreenLimit > 0 
                    ? ExtendedGreenLimit 
                    : Phases[CurrentPhaseIndex].Duration;
                if (TimeInCurrentPhase >= effectiveDuration)

                    TimeInCurrentPhase = 0.0;
                    ExtendedGreenLimit = 0.0;
                }
            }
        }

            if (CurrentState == LightState.Green)
            {
                CurrentState = LightState.Yellow;
                TimeInCurrentPhase = 0.0;
                ExtendedGreenLimit = 0.0;
            }
        }

using System;

namespace SAi_KR
{
    public class NeuralNetwork
    {
        private readonly int _inputSize;
        private readonly int _hiddenSize;
        private readonly int _outputSize;

        public double[,] WeightsInputHidden { get; set; }
        public double[] BiasHidden { get; set; }
        public double[,] WeightsHiddenOutput { get; set; }
        public double[] BiasOutput { get; set; }

        public int TotalWeightsCount => (_inputSize * _hiddenSize) + _hiddenSize + (_hiddenSize * _outputSize) + _outputSize;

        public NeuralNetwork(int inputSize, int hiddenSize, int outputSize, Random? rand = null)
        {
            _inputSize = inputSize;
            _hiddenSize = hiddenSize;
            _outputSize = outputSize;

            WeightsInputHidden = new double[inputSize, hiddenSize];
            BiasHidden = new double[hiddenSize];
            WeightsHiddenOutput = new double[hiddenSize, outputSize];
            BiasOutput = new double[outputSize];

            InitializeWeights(rand ?? new Random());
        }

        private void InitializeWeights(Random rand)
        {
            double limitHidden = Math.Sqrt(6.0 / (_inputSize + _hiddenSize));
            for (int i = 0; i < _inputSize; i++)
            {
                for (int j = 0; j < _hiddenSize; j++)
                {
                    WeightsInputHidden[i, j] = (rand.NextDouble() * 2.0 - 1.0) * limitHidden;
                }
            }

            for (int j = 0; j < _hiddenSize; j++)
            {
                BiasHidden[j] = 0.0;
            }

            double limitOutput = Math.Sqrt(6.0 / (_hiddenSize + _outputSize));
            for (int i = 0; i < _hiddenSize; i++)
            {
                for (int j = 0; j < _outputSize; j++)
                {
                    WeightsHiddenOutput[i, j] = (rand.NextDouble() * 2.0 - 1.0) * limitOutput;
                }
            }

            for (int k = 0; k < _outputSize; k++)
            {
                BiasOutput[k] = -0.8;
            }
        }

        public double[] Forward(double[] inputs)
        {
            if (inputs.Length != _inputSize)
                throw new ArgumentException($"Ожидался вектор входов размерности {_inputSize}, получено: {inputs.Length}");

            double[] hidden = new double[_hiddenSize];
            for (int j = 0; j < _hiddenSize; j++)
            {
                double sum = BiasHidden[j];
                for (int i = 0; i < _inputSize; i++)
                {
                    sum += inputs[i] * WeightsInputHidden[i, j];
                }
                hidden[j] = Math.Tanh(sum);
            }

            double[] outputs = new double[_outputSize];
            for (int k = 0; k < _outputSize; k++)
            {
                double sum = BiasOutput[k];
                for (int j = 0; j < _hiddenSize; j++)
                {
                    sum += hidden[j] * WeightsHiddenOutput[j, k];
                }
                outputs[k] = 1.0 / (1.0 + Math.Exp(-sum));
            }

            return outputs;
        }

        public double[] GetWeights()
        {
            double[] weights = new double[TotalWeightsCount];
            int idx = 0;

            for (int i = 0; i < _inputSize; i++)
                for (int j = 0; j < _hiddenSize; j++)
                    weights[idx++] = WeightsInputHidden[i, j];

            for (int j = 0; j < _hiddenSize; j++)
                weights[idx++] = BiasHidden[j];

            for (int j = 0; j < _hiddenSize; j++)
                for (int k = 0; k < _outputSize; k++)
                    weights[idx++] = WeightsHiddenOutput[j, k];

            for (int k = 0; k < _outputSize; k++)
                weights[idx++] = BiasOutput[k];

            return weights;
        }

        public void SetWeights(double[] weights)
        {
            if (weights.Length != TotalWeightsCount)
                throw new ArgumentException($"Ожидался массив весов длины {TotalWeightsCount}, получено: {weights.Length}");

            int idx = 0;

            for (int i = 0; i < _inputSize; i++)
                for (int j = 0; j < _hiddenSize; j++)
                    WeightsInputHidden[i, j] = weights[idx++];

            for (int j = 0; j < _hiddenSize; j++)
                BiasHidden[j] = weights[idx++];

            for (int j = 0; j < _hiddenSize; j++)
                for (int k = 0; k < _outputSize; k++)
                    WeightsHiddenOutput[j, k] = weights[idx++];

            for (int k = 0; k < _outputSize; k++)
                BiasOutput[k] = weights[idx++];
        }

                engAI.InflowRashpilevskayaNorth = sourceEngine.InflowRashpilevskayaNorth;

                // Переносим обученные веса нейросетей агентов
                for (int i = 0; i < Math.Min(sourceEngine.Agents.Count, engAI.Agents.Count); i++)
                {
                    engAI.Agents[i].Brain.SetWeights(sourceEngine.Agents[i].Brain.GetWeights());
                }
            }
            engAI.CurrentControlMode = ControlMode.IntelligentAgents;

            int aiQueueSum = 0;
            int aiMaxQ = 0;

            for (int s = 0; s < totalSteps; s++)
            {
                engAI.Step(0.1);
                int q = engAI.GetTotalQueue();
                aiQueueSum += q;
                if (q > aiMaxQ) aiMaxQ = q;

                if (s % 100 == 0 && progressCallback != null)
                {
                    progressCallback(totalSteps / 2 + s / 2, totalSteps);
                }
            }

            var aiVehicles = engAI.AllLanes.SelectMany(l => l.Vehicles).Concat(engAI.CompletedVehicles).ToList();
            report.AIAvgWait = engAI.GetAverageWaitTime();
            report.AITotalPassed = engAI.CompletedVehicles.Count;
            report.AIAvgQueue = (double)aiQueueSum / totalSteps;
            report.AIMaxQueue = aiMaxQ;
            report.AITotalStops = aiVehicles.Sum(v => v.StopCount);
            report.AIGreenWavePct = aiVehicles.Count > 0 
                ? (double)aiVehicles.Count(v => v.StopCount == 0) / aiVehicles.Count * 100.0 
                : 0.0;

            report.AIDelayOkt = CalculateIntersectionDelay(engAI, 0);
            report.AIDelayRash = CalculateIntersectionDelay(engAI, 1);
            report.AIDelayKras = CalculateIntersectionDelay(engAI, 2);

            progressCallback?.Invoke(totalSteps, totalSteps);
            return report;
        }

        private static double CalculateIntersectionDelay(SimulationEngine engine, int nodeIndex)
        {
            if (nodeIndex >= engine.Intersections.Count) return 0.0;
            var node = engine.Intersections[nodeIndex];
            var cars = node.IncomingLanes.SelectMany(l => l.Vehicles).ToList();
            return cars.Count > 0 ? cars.Average(c => c.TotalWaitTime) : 0.0;
        }
